# DSRC 上位机用例移植

## 适用范围与边界

当需求包含“移植、迁移、按原上位机复现、对照旧日志或旧流程”时使用本 skill。先遵守 `AGENTS.md`；它定义项目边界、实现分层、敏感输入和验证标准，本 skill 补充从旧流程审计到新上位机落地的完整移植工作流。

- 旧 C++/MFC 代码只能只读分析；不得修改、链接或直接复制其实现。
- 目标始终是当前 C#/.NET Framework 4.8、WinForms、x86 解决方案。
- 纯新功能、已证实流程的重构、界面或 DLL 开发使用 `dsrc-csharp-host-developer`。
- 同一任务既要迁移又要实现时，先完成本 skill 的审计产物，再由开发流程实现。

## 移植工作流

### A. 旧上位机流程审计

1. 建立证据表：定位旧界面入口、线程或调度、最终执行函数、初始化台发、配置/INI、密钥和算法来源。
2. 还原完整时序：记录 BST/VST、GetSecure、Transfer、SetMMI、EventReport、等待、重试、轮次、动态字段变化及各分支清理动作。
3. 还原判定：分别记录 DLL 返回码、是否收到回复、外层长度、APDU 状态、业务数据比较和最终通过条件。
4. 逐字节校对：外层 TransferChannel、DataList/APDU 边界、CLA/INS/P1/P2/Lc/Data/Le、随机数、密钥索引和 MAC 输入；动态字段必须标注来源。
5. 对照旧组帧代码或模板、旧实机日志和新实测帧，列出帧顺序、字段、时序、判定和异常清理差异。
6. 无法证实的内容标记为待确认；只有证据充分的结论才能进入当前 C# 实现。

### B. 新上位机移植设计

1. **确定现有入口**：定位当前标准测试窗体、测试树节点、稳定用例路径和现有服务；确认是新增叶子、扩展现有处理器还是新增专用服务。
2. **建立映射矩阵**：为每个旧用例记录新用例名称、树路径、处理器入口、配置来源、帧序列、状态判定、结果文件和截图行为；未实现项保持不可执行，不创建伪造通过路径。
3. **划分职责**：Designer 只维护静态控件和显式事件；窗体后置只做选择、状态、取消和服务调用；协议组帧/解析、DLL 调用、配置读取和结果判定放入职责明确的服务类。
4. **迁移数据流**：按旧流程把初始化、动态字段、每一帧请求/回复、LLC/MACID/BID/UnixTime/算法、等待/重试和 EventReport 映射到新服务；调用方显式传递参数，不依赖未说明的全局状态。
5. **接入测试调度**：为每个叶子提供清晰可跳转的处理器入口，复用现有父子勾选、顺序批量、统一取消令牌、日志、结果文件和汇总截图机制；测试未连接设备时必须明确失败或停在可诊断状态。
6. **接入界面说明**：双击用例只展示流程和判定依据，标明已迁移、待确认或原版未实现；不得在说明入口隐式启动通信。

### C. 新旧实现对照与验证

1. 先做离线帧回归：比较旧模板/日志与新组帧的帧顺序、长度、动态字段、APDU 边界、状态字、LLC 和 MAC 输入。
2. 再做失败路径回归：验证超时、无回复、错误状态、长度异常、DLL 返回失败、取消和 EventReport 收尾，不把 DLL 成功替代整例通过。
3. 构建 `Debug|x86`，检查受影响窗体 Designer 能打开、事件能双击跳转、项目文件说明已同步；有硬件时再按同一矩阵执行实机验证。
4. 交付时列出已完成映射、与原程序确认的差异、未实现/待确认项、构建结果和仍需实机确认的范围。

## 停止条件与交付

- 每次移植至少留下流程/判定矩阵和帧差异记录，再开始实现和验证。
- 旧行为与文档或实机冲突时保留冲突证据，不根据相邻用例补全字段。
- 临时兼容判断限定到精确用例或帧，写明依据、`TODO` 和删除条件。
- 缺失信息若会实质改变协议字段、长度、算法、ABI、密钥或验收判定，停止并请求依据；仅影响格式或非关键 UI 的小差异可沿用当前项目风格并在交付中注明。
