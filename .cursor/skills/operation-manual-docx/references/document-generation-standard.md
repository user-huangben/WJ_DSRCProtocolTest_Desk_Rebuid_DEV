# DOCX 生成与验收规范

## 内容

- 标题直接说明文档对象和用途，正文先交代适用范围、前置条件和主要操作目标。
- 只记录源码、界面和实测证据能够确认的功能；占位功能必须明确标注。
- 不写入密钥、密文、完整卡数据、正式配置或未脱敏日志。

## 版式

- 使用 Word 标题样式建立清晰层级，标题统一为黑色。
- 正文使用易读中文字体和字号，避免连续大段文字。
- 表格列宽按内容设置，允许自动换行，不使用可能截断文字的固定行高。
- 截图、图注和对应说明尽量保持在相邻页面区域，避免大块空白。
- 操作密集区域使用“编号截图 + 对应说明”，编号必须一一匹配。

## 工具

- 创建或编辑前执行 `../scripts/mark_artifact_operation_started.mjs`。
- 使用 `../scripts/build_manual.py` 生成当前项目操作说明。
- 使用 `../scripts/render_docx.py` 将 DOCX 渲染为逐页 PNG。

## 验收

1. 打开并检查每一张渲染 PNG。
2. 确认无文字截断、重叠、乱码、缺图、异常空白页或表格分页错误。
3. 检查标题层级、截图编号、图注、中文字体、页眉页脚和页码。
4. 修正文档后重新渲染，直到所有页面通过检查。
5. 对外交付只提供最终 DOCX；渲染图片作为内部验收产物保留。
